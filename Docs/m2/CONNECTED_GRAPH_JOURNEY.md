# Connected graph learner journey

## What is connected

When the existing team API mounts the beta (`TUTOR_BETA_CONFIG`), its browser navigation offers **Connected maths tutor**. A student signs in with a token accepted by the existing student API; the server derives the learner ID from that token. The credential is held in page memory, not browser storage. A random session ID may be retained in this tab's session storage; active or interrupted graph sessions can also be found after signing in through the authenticated `GET /chat/active` endpoint.

The connected conversation, approved practice and quiz questions, and displayed plan use the same graph learner and server. Quiz results update the graph's learner state and plan; this is distinct from the anonymous beta profile, its conversations, observations, cards and plan. Neither sign-out nor clearing the anonymous beta history deletes the other record. This is a connected graph path within the beta shell, not a merge or migration of the two identity stores. The standalone anonymous beta does not advertise the connected navigation.

The graph now supports chapter-pinned, source-backed conversations for **Class 10 quadratic equations, arithmetic progressions and introduction to trigonometry** using 22 local normalized cards. Checked practice is also connected for AP term/sum and trigonometric right-triangle ratio questions after teacher publication. Separate synthetic development quizzes and quiz-driven chapter plans are now connected for AP and trigonometry; trigonometry practice now has limited error hypotheses, while AP diagnosis remains unavailable. Those chapters do not use quadratic questions or plans. [Quiz and plan details](CHAPTER_QUIZZES_AND_PLANS.md). [Chapter practice](CHAPTER_PRACTICE.md). These cards are not the full 8–12 textbook index and human content review is pending. Teacher-published questions are still required. The local stub-model walkthrough does not establish a real-model, cited active-problem hint or human educator approval. [Chapter scope and citation snapshots](CHAPTER_SCOPED_RETRIEVAL.md).

> **Development content:** Quiz questions come from a separate six-item synthetic quadratic pack with explicit quiz permission. Its content review is pending; teacher approval is still required for the mounted and graph workflows. [Mode and provenance details](KEY_AND_MODE_INTEGRITY.md).

## Assessment behavior and recovery

For authenticated graph API requests sharing the same local tutor database, a durable learner-scoped reservation is made before each turn. It is retained while the quiz is active or a graph turn remains interrupted. Another session for that learner receives `409`; other authenticated learners remain separate. The browser disables new conversation during the quiz, hides the plan until completion and provides **Leave quiz**, which ends an unfinished quiz without recording a score. A pending interrupted turn must be recovered before it can be left. At sign-in, the browser checks the active session; after an uncertain request it asks the learner to check the conversation and uses the existing resume endpoint instead of automatically resubmitting the message. The quiz-result ledger applies completed results at most once.

`/chat` now reports `quiz_active`; `/chat/{session_id}/history` reports `quiz_active` and `interrupted`. Student-authenticated `/chat/active` returns only that student's active or interrupted session; `/chat/leave` operates only on a session belonging to that student. A recognized distress message from another session while a reservation exists gets the existing static urgent guidance without saving the turn or claiming a notification. It is marked `not_saved_urgent`; phrase detection is limited. Normal graph handoff and beta urgent behavior retain their separately documented limits.

The reservation is reconciled against graph checkpoints under the existing file-backed publication lock. Synthetic tests cover a second API instance, simultaneous starts, failure before a checkpoint, interruption after the quiz transaction, recovery, leaving and teacher edits. The lock only protects cooperating processes using the same local database and lock path. Direct graph calls that bypass the API, another database or host, the anonymous beta profile, and direct SQLite writes are outside this protection. Existing active graph checkpoints created before reservations were introduced are not automatically discovered; the guard applies once those sessions go through the new API path. There is no general client-turn idempotency guarantee. A later [graph deletion workflow](LEARNER_DATA_LIFECYCLE.md) adds teacher-authorized logical cleanup and documents retention/backup limits.

## Reproducing the development check

Configure the team API's beta mount and local authorized data as described in [the run guide](../RUN_GUIDE.md) or the repository's deployment documentation. Use stub mode for offline testing. With a configured student and a teacher-published set: open `/beta/#connected`, sign in as the student, select a chapter and ask a question. Request guided practice or start a quiz after a teacher has separately approved a set for that chapter and mode. Start a new conversation to change chapters. AP/trigonometry plans appear after a completed chapter quiz. Credentials, source rights, educator review and external service authorization must be provisioned separately for a real demonstration.

An assistant-operated localhost walkthrough used a synthetic learner, a synthetic teacher publication, a synthetic passage and the stub model. It observed a Socratic exchange, a three-question quiz with an unparseable response held open, a quiz-informed plan revision, refresh and sign-in recovery, and an unfinished quiz being left without a score. These observations are not cross-browser, accessibility, live-model or human-review evidence. Automated two-learner, publication, recovery and concurrency results are recorded in [verification](VERIFICATION.md).


Checked right-triangle practice now supports three provisional error hypotheses with explicit ambiguity handling. See [trigonometry hypotheses](TRIGONOMETRY_HYPOTHESES.md); broader diagnosis remains incomplete.
