# Integrated Compose preparation and readiness

The existing Compose configuration starts the graph API and Streamlit interface. The additive `docker-compose.integrated.yml` overlay prepares the mounted Socrates beta using an externally supplied SQLite index, registers it against a required expected SHA-256, and makes the API health check depend on `/health/ready`. The supplied file is mounted read-only; code, public teaching content and configuration enter the image, while the index and credentials do not. The overlay forces the stub model and offline beta. A compatible, authorised index and independently obtained expected hash are prerequisites, not included in Git.

The container startup creates a separate registry in `/app/var/beta` inside the existing persistent volume. On restart it validates the input hash and reuses the same active ID, path and hash. It refuses to replace a different active dataset; choose an explicit migration or a separate volume after preserving existing state. It does not rewrite the supplied index. Build-context exclusions include `Directions/`, private evaluation data, frozen builds, local beta configuration, environments and secrets.

`GET /health/ready` returns 200 only when the graph database and checkpointer respond, the three chapter reference sets exist, and the configured beta's active registered index is accessible and has passages. When `TUTOR_REQUIRE_BETA=1`, an unmounted beta is not ready. Without that requirement, the existing graph-only service can be ready and reports beta as `not_configured`. The check returns component states without local paths. The beta registry verifies the recorded index hash when loading or when its observed file metadata changes; this is not a defense against a privileged process that can alter data and metadata. Readiness does not establish source accuracy, teacher approval, live-model quality or complete curriculum coverage.

## Evidence and unresolved gate

Docker and Podman executables were not available on this computer. The overlay was parsed and its required settings checked, but Compose interpolation, image builds, container health checks, volume behavior and a fresh-machine run have **not** been verified. A local synthetic-index subprocess exercised the actual preparation entrypoint, readiness endpoint, beta page, synthetic teacher approval and student practice using the stub model. The first startup attempts exposed a wrong Python executable and Windows path quoting problem; the entrypoint now runs Uvicorn through its current Python runtime. A separate registry was prepared against the existing local 10,878-passage index, matching its existing recorded hash and returning scoped hits for all three target chapters without changing the source file. The existing registry hash is not independent proof of provenance.

That real-index smoke initially found no trigonometry hits for “sine cosine”. Query expansion now retains those English words and adds `sin` and `cos` (also `tangent`/`tan`), with a synthetic regression and a successful repeat of the same local query. This is a targeted retrieval fix, not a broad natural-language evaluation. Human content review, source redistribution rights, an independent evaluator, live-model authorization and actual Compose acceptance remain open.
