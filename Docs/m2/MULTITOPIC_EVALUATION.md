# C1/C2 quadratic and trigonometry development smoke

The new matched development configurations use the same two synthetic cards, seed, turn limit, public practice pool and stub-model settings. One card models a learner who may divide a quadratic equation by `x` and lose zero; the other models confusion about which triangle sides are opposite and adjacent when the reference angle changes. Each card is assigned its own chapter-specific, developer-authored pre/post problem pair. The cards and examples are development instruments, not independent or human-reviewed evaluation data. They do not use or alter held-out material.

The harness now passes the selected chapter to the tutor and rejects a card whose assigned concepts belong to another chapter. It records a registered practice attempt only after the simulator actually sends it; it changes simulated mastery only when the tutor's deterministic grader also accepts the answer. An unsubmitted last-turn answer no longer changes simulated mastery. A disagreement between the simulator and grader is counted as a failure. New practice-question givens are included as context for leak checks against a different earlier problem, while the entire reply remains scanned; a repeated post-quiz question is separately recorded as question exposure, and explicit answer disclosures are still checked. Run directories use unique IDs and are never overwritten deliberately.

## Observed working-tree run

On 4 November, matched stub runs `m2_multitopic_c1-20261104-113942-cf2cdbeb904a` and `m2_multitopic_c2-20261104-113945-e8f2c603dd89` each completed two sessions and 16 turns with zero execution failures, timeouts or model calls. Each named the seeded quadratic misconception and did not name the seeded trigonometry misconception. Each received six registered practice attempts; none was checked correct. The simulator's one-item pre and post checks were both incorrect for both cards. The answer-leak heuristic counted zero full/partial leaks after treating the other practice problem's givens as context, and recorded no post-question exposure. The earlier working-tree run counted two partial leaks because it treated the `= 0` in a newly presented quadratic equation as an answer to the previous problem; the original output is preserved. These are tiny, author-controlled development observations and do not establish human learning, reliable model quality, independent evaluation, absence of leaks or superiority of either arm. The configured gate checks only execution failures, timeouts, full-leak heuristic and session count; a passing gate does not mean the tutor performed well.

The trigonometry result is consistent with the graph's documented lack of chapter-specific misconception diagnosis. The simulator can keep repeating its seeded wrong rule, and its gain model is synthetic. A two-card sample and its bootstrap interval cannot support a statistical comparison. Both arms share code and services; no live provider was called.

## Correction to earlier wording

The existing `task_success` key follows the pre-registered formula: seeded misconception named, no full leak, and simulated post score at least pre score. It does **not** count problems solved. Earlier notes saying that each arm “solved” or “completed” one of two tasks overstated what that proxy measures. Historical output files are preserved; older simulated gains may also reflect the unsent-answer bug and should not be compared directly to corrected runs. New reports label this metric as a diagnosis/quiz proxy and separately report submitted and checked-correct practice attempts.
