## Findings

1. **The POC tutor's model use is narrow.** It calls the model only when the planner focuses a named misconception (the `tutor` node), or to diagnose. In these sessions the planner always took the item-hint and grading paths, which are templates. **For R3:** E1 and the cost estimate need the specialists on `create_agent` with the course model. Until then, a "live" tutor run measures templates.
2. **The judge agrees with the code leak checker** on all 40 turns (none leaked). It also scores the template turns poorly:
   - mistake identification Yes on 15 of 40;
   - guidance Yes on 14 of 40;
   - only 1 turn targets a seeded misconception.

   That is the room the real tutor agents should fill. These labels are unvalidated until the kappa gate on Sat 7.
3. **The LLM student voice works:** natural, informal, and every answer value kept (6 of 6, no fallbacks). But 2 of 6 openers dropped the equation, which leaves the tutor nothing to diagnose. **Fixed after the run:** the voice must now also keep the equation. Re-check on the next live run.
4. **Cost logging gaps, fixed or assigned:**
   - The judge now records tokens per call.
   - The voice's tokens aren't logged yet.
   - Tutor cost should come from OpenRouter's `usage.cost` (R3, in `llm.py`).

## Recommendation

- **Spend no more live calls on the POC tutor.** The next live run comes when R3's agents call the model. Use `dev_live.toml` (capped at USD 0.10) first, then size E1.
- **Judging every turn of the planned experiments:** about 5,800 turns × USD 0.0004 ≈ **USD 2.3**. Affordable. Judge everything reported, and only a sample during development.
- **Re-run this spike** when the tutor is model-driven, to replace the estimate in `eval/README.md` (USD 0.006 per session) with a measured one.
