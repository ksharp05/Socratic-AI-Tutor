# Memory policy - implemented local development behavior

**4 November 2026. Scope:** authenticated graph learner records in the Milestone 2 local demo. Synthetic learners only; this document is not approval to enroll real students. The anonymous beta has a separate browser identity and store. This policy describes current code; the older plan's proposed 30-day periods and automatic summarization are not implemented.

| Data and purpose | Storage / access | Current lifetime and deletion |
|---|---|---|
| Pseudonymous ID and alias; link a learner across sessions | Graph SQLite `learners`; bearer-token identity; teacher listing | Retained until teacher-authorized deletion. Use synthetic aliases; arbitrary names are not reliably removed. |
| Concept observations, suspected misconceptions, explanation outcomes and chapter plans; choose the next teaching move | Graph learner tables; own learner views and teacher views | Deleted with the learner, including quiz-application ledger, stuck-session state, alerts and active-session reservations. These observations do not establish human learning. |
| Conversation messages, active problem/quiz, saved references and interrupted graph state; history/recovery | Registered graph checkpoint SQLite files; student session ownership checked by the API | All discoverable target threads, historical checkpoints and pending writes are logically deleted. Full checkpoint histories are retained until deletion; there is no automatic transcript expiry or summarization. |
| Scrubbed tool/decision/model traces; debug and audit behavior | Graph `trace_events`; internal code/evaluation access and a teacher-only projected session trace | Target-session rows and exact learner-linked API rows are deleted. Tool response text is logged by length; input redaction is rule-based and incomplete. |
| Minimal deletion record; prevent stale credentials or startup seeding restoring a deleted learner | Graph `learner_deletions`; trusted server/teacher operation | Retains pseudonymous ID, request/teacher identifiers, timestamps, status and aggregate receipt counts. Pending work lists are cleared on completion. No automatic expiry or reenrollment workflow is defined. |
| Shared source cards, question approvals, checked key cache and aggregate metrics | Shared teaching/runtime stores | Preserved by learner deletion. These must not contain learner transcripts. Metrics have no learner-ID label; existing aggregate counts remain. |

**Authorization and deletion.** A teacher uses **Data requests** in the Streamlit UI or authenticated `DELETE /learners/{id}` after validating the request. Students and agents cannot execute deletion. A durable marker blocks learner data access before cleanup. If cleanup is interrupted, teacher retry resumes the stored work list; another learner's data is preserved. The signed-in record returns HTTP 410 thereafter, including after restart; the old token configuration itself is not revoked. See [workflow, recovery and evidence](m2/LEARNER_DATA_LIFECYCLE.md).

**Context and disclosure.** Prompts use selected observations/passages rather than the entire saved checkpoint; the optional contextual-preview adapter uses the last four messages, and anonymous beta dialogue uses six exchanges. This is prompt selection, not transcript deletion. Server-side answer keys and private final-evaluation material must remain outside model context. Provider transfer and retention require separate authorization; no live provider was used to verify deletion.

**Limits.** This is logical SQL deletion, not forensic erasure of SQLite free pages/WAL, storage media, backups, copied checkpoints, browser caches, server/proxy logs, screenshots, downloaded exports, evaluation artifacts or provider-side copies. Other processes can retain small in-memory call counters until restart; ordinary graph operations are blocked by the deletion marker. Unknown legacy checkpoint files and ownerless legacy state require operator inventory; mixed-owner threads are quarantined for manual review. Do not restore a pre-deletion backup to an accessible service without applying the deletion obligations to every restored store. No backup-expiry schedule or automatic TTL is enforced. The anonymous beta's **Clear this browser's learning history** is a separate action and does not delete the graph record. A production retention/consent/access policy remains to be approved.

[Actual synthetic API example](m2/MEMORY_POLICY_EXAMPLE.json) shows selected learner fields, a redacted student message, rejected student deletion, the teacher receipt and the unchanged peer check. It is a projection of existing responses, not a new full export service.
